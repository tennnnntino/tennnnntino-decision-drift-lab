# Contributor and coding agent contract

This is an independent public synthetic research testbed.

1. Keep source, structured tests and limitations aligned. Never claim a test ran unless it actually ran.
2. No private repositories, external project names, owner instructions, business data, personal details, secrets, unlicensed third-party code or historical imports.
3. No model-triggered side effects and no implicit authorization. Artificial fixture approvals must always be labelled simulated.
4. Do not include real API keys or provider clients in sample fixtures. No traffic required for default run.
5. Make changes small, testable and evidence-backed. Preserve backwards-compatible CLI entry points where feasible.
6. Report what is implemented, planned and unknown separately. Do not market the tool as security enforcement or an academically validated benchmark.
7. Keep the 20 perspective review **as a set of reproducible criteria**, not claims of real specialists reviewing the code.
8. Before any future deploy, public release, Git commit or network action: request an explicit human authorization.
9. For public reports, disclose null denominators, baseline choices and sampling limitations.
10. No silent merge of data, claims or decisions.


## V1.3 generated challenge boundary

The 100-case challenge is explicitly generated, not 100 independent expert judgements.
Preserve the distinction between a PASS control, an intentionally rejected FAIL control,
matched expected results, external validity and actual authenticated authorization.
No public release, push, GitHub repository creation or deployment without an explicit
Owner Human Gate for the precise artifact bytes. No private project references or sources.


## V1.4 candidate-label boundary

Labels drafted by a model are candidates. Never describe them, or anything computed from them,
as human-labelled, gold, validated or accurate. Never set a case's review state on behalf of a
person. Confusion matrices and rates are produced only for cases with a recorded human review.
Do not edit `research/handoff-corpus-v1_4/heldout.json` or tune `ddlab/baselines.py` against it;
if either changes, regenerate the results snapshot and say so in the changelog.
No conversation-provider adapter, model call or real conversation without a separate privacy
decision by the owner. The importer document is a proposal, not a feature.


## V1.4.1 policy and labelling boundary

The authorization policy is operator configuration. Never read it, or any part of the approval
requirement, from an analysed case, and never describe the simulated approval or the policy as
authentication. Do not add an exemption to the packaged policy without a written rationale.
Do not create `heldout-human.json` or `independent-heldout.json` yourself: they must come from a
person through the label form. Blind material must not contain titles, candidate labels,
findings or baseline output. Regenerate `docs/policy.mjs`, the results snapshot and the ProofPack
with their tools; do not edit generated files by hand.
